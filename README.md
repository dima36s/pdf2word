# PDF → Word

[![CI](https://github.com/dima36s/pdf2word/actions/workflows/ci.yml/badge.svg)](https://github.com/dima36s/pdf2word/actions/workflows/ci.yml)
[![Open in GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/dima36s/pdf2word)

## 👉 [Открыть конвертер: dima36s.github.io/pdf2word](https://dima36s.github.io/pdf2word/)

Работает прямо в браузере: ничего устанавливать не нужно, документы не отправляются на сервер.
Первый запуск загружает модуль конвертации (~50 МБ), дальше он берётся из кэша.

---

Веб-приложение для конвертации PDF в редактируемый документ Word (DOCX) с сохранением структуры:
абзацы, шрифты, начертания и цвета, списки, таблицы (с рамками и без), изображения, многоколоночная
вёрстка, колонтитулы. Отсканированные страницы распознаются (OCR): текст становится редактируемым,
линии таблиц — настоящими таблицами Word, графики и печати сохраняются картинками.

Интерфейс работает по образцу iLovePDF: перетащили файлы → «Конвертировать в Word» → скачали DOCX
(или все файлы одним ZIP). Внешних CDN и шрифтов нет — сервис работает во внутренней сети без интернета.

## Возможности

| | |
|---|---|
| Текстовые PDF | абзацы, выравнивание, отступы, жирный/курсив/цвет, маркированные и нумерованные списки |
| Таблицы | с рамками, без рамок, с заливкой ячеек; строки растягиваются, текст не обрезается |
| Вёрстка | несколько колонок, колонтитулы, «карточки» с фоном из PDF, сделанных в браузере |
| Проектная документация | рамка листа, основная надпись и боковой штамп по ГОСТ, шапка с логотипом — в колонтитулах Word; таблицы спецификаций — настоящими таблицами; номер листа — полем; заголовки — стилями «Заголовок 1–4»; содержание с отточием |
| Сканы (OCR) | Tesseract, автоповорот страниц, выравнивание наклона, подавление шума, восстановление таблиц по линиям, определение жирного шрифта и цвета текста, сохранение иллюстраций |
| Защищённые PDF | ввод пароля на карточке файла; пароль не сохраняется на сервере |
| Параметры | диапазон страниц (`1-3, 5, 8-`), язык распознавания, OCR вкл/выкл |
| Excel | кнопка «Excel» рядом с DOCX: таблицы и текст по листу на каждую страницу PDF — объединённые ячейки, границы, заливка, числа числами; строки спецификаций — по записям |
| Пакетная обработка | несколько файлов сразу, очередь, скачивание всех результатов ZIP-архивом |
| Приватность | файлы удаляются автоматически (по умолчанию через 60 минут) или кнопкой «×» |

## Две версии

| | Браузерная (GitHub Pages) | Серверная (Docker) |
|---|---|---|
| Где работает | в браузере пользователя (Python в WebAssembly — Pyodide) | на сервере (FastAPI) |
| Установка | не нужна — [ссылка](https://dima36s.github.io/pdf2word/) | `docker compose up` |
| Где файлы | не покидают компьютер | на сервере, удаляются через 60 мин |
| OCR сканов | Tesseract.js (rus, eng) | Tesseract (любые языки) + автоповорот |
| Скорость | в 2–3 раза медленнее, первый запуск ~50 МБ | быстрее, очередь на несколько файлов |

Код конвертации общий (`app/`): браузерная версия вызывает те же функции по шагам
(`app/webapi.py`, `web/worker.js`). Сборка сайта — `python scripts/build_web.py --out _site`,
публикация — workflow `.github/workflows/pages.yml` при каждом push в `main`. Тот же каталог
`_site` можно положить на любой внутренний веб-сервер — для корпоративного контура это самый простой
вариант: ни Python, ни Docker на сервере не нужны.

## Быстрый старт

### Ссылка для тестирования

**Вариант 1 — GitHub Codespaces (полная версия с OCR, ссылка временная).**
Нажмите **Open in GitHub Codespaces** вверху → **Create codespace**. Через 3–5 минут окружение
соберётся, сервер запустится сам, а в терминале **server** появится рамка со ссылкой вида
`https://<имя>-8000.app.github.dev` — порт открывается публично автоматически, ссылку можно
отправлять. Если в рамке написано, что открыть порт не удалось: вкладка **PORTS** → строка 8000 →
правый клик → **Port Visibility → Public**.

Ссылка живёт, пока запущен codespace: он останавливается после периода бездействия (по умолчанию
30 минут, можно до 240 — [github.com/settings/codespaces](https://github.com/settings/codespaces)),
запросы тестировщиков продлевают работу. Повторный запуск — github.com/codespaces → ваш codespace →
**Open**; адрес при этом сохраняется. Время работы расходует бесплатную квоту Codespaces вашего аккаунта.

**Вариант 2 — Render (постоянная ссылка, без OCR).**

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/dima36s/pdf2word)

Войдите через GitHub → **Apply**. Через 5–10 минут сервис будет доступен по адресу вида
`https://pdf2word-xxxx.onrender.com`, и он обновляется сам после каждого push в `main`.
Бесплатный тариф: 512 МБ памяти и 0,1 CPU, засыпает после 15 минут без запросов (просыпается
около минуты). Распознавание сканов на нём отключено — ему нужно ~600 МБ памяти; настройки — в
`render.yaml`.

На обоих тестовых стендах в интерфейсе показывается плашка «не загружайте конфиденциальные
документы» (`DEMO_NOTICE`).

```bash
# системные пакеты: Tesseract с русским языком и шрифты Liberation
sudo apt install tesseract-ocr tesseract-ocr-rus fonts-liberation      # Debian/Ubuntu
# brew install tesseract tesseract-lang                                 # macOS

python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

`TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe`. Без Tesseract сервис тоже работает —
сканы просто вставляются в Word картинками.

## Как это устроено

```
браузер ── upload ──► FastAPI ──► data/tasks/<id>/input.pdf + превью
        ◄─ прогресс ─┘   │
                         └─► очередь (asyncio, CONVERT_WORKERS) ──► отдельный процесс на файл:

  1. открыть PDF, проверить пароль, расшифровать в память
  2. классифицировать страницы: текст / скан / скан со скрытым OCR-слоем
  3. сканы → OCR: рендер 300 dpi → автоповорот → выравнивание наклона → поиск линий таблиц
     → Tesseract hOCR → новая страница с настоящим текстом, линиями и вырезанными иллюстрациями
  4. «карточки» с фоном (PDF из браузера) → фон убирается, текст остаётся
  5. pdf2docx + исправления app/textfix.py
  6. постобработка DOCX: шрифты Liberation → Times New Roman/Arial, высота строк таблиц «не менее»
```

Каждая конвертация — отдельный процесс: падение или утечка памяти в одном документе не влияет на
остальные, зависший процесс убивается по таймауту. Состояние задач хранится в файлах.

### Проектная документация: рамки, штампы, колонтитулы

По замечаниям тестировщиков (спецификации, опросные листы, текстовые части с рамкой и штампами):

- **Таблица переносилась картинкой, а текст ложился поверх.** pdf2docx считал «рисунком» всю область,
  если в ней есть хоть одна «непрямая» линия. В выгрузках из САПР непрямыми оказывались ломаные
  (сетка таблицы одной командой пути) и линии с микронаклоном, а логотип в штампе превращал в
  картинку всю рамку листа. Кроме того, таблица внутри рамки попадала на второй уровень вложенности
  контуров и растрировалась всегда. Теперь прямота проверяется по отрезкам, а картинкой вырезаются
  только сами кривые (логотип) — `app/geometry.py`, `app/vectorfix.py`.
- **Вертикальный текст бокового штампа** — следствие предыдущего: когда штамп стал таблицей, текст
  в ячейках идёт снизу вверх, как в PDF.
- **Штамп «уезжал» на следующую страницу, шапка и штамп дублировались вручную.** Оформление листа
  (рамка, основная надпись 185 мм, боковой штамп, шапка с логотипом и линией, нижний штамп-рамка,
  а также просто повторяющиеся верх и низ страниц) находится автоматически (`app/furniture.py`) и
  переносится в колонтитулы Word (`app/headers.py`): страница разбирается без этих областей, а сами
  области — отдельными проходами pdf2docx (`app/regionfix.py`). Номер листа становится полем PAGE,
  одинаковые колонтитулы соседних листов связываются («Как в предыдущем разделе»), рамка рисуется
  за текстом, боковой штамп — «плавающая» таблица в точных координатах. Поля страницы выставляются
  по шапке и штампу, поэтому текст не перекрывает штамп и не уходит на лишние листы. Если что-то
  пошло не так, документ собирается по-старому, без колонтитулов.
- **Пропадали одиночные линии** (линия под шапкой, линия в штампе) — теперь это граница абзаца.
- **Заголовки** с номерами («2», «2.1», «2.2.1») и стандартные разделы («Содержание», «Введение»,
  «Приложение А») получают стили «Заголовок 1–4» с сохранением вида из PDF — в Word работает
  область навигации и автоматическое оглавление. Заголовок, разложенный в безрамочную таблицу
  «номер | текст», снова становится абзацем (`app/docxfix.py`).
- **Содержание:** отточие из точек заменяется табуляцией по правому краю с заполнителем —
  номера страниц стоят ровно у края при любом шрифте.
- **Текст, нарисованный линиями** (шрифты SHX из AutoCAD/nanoCAD, текстового слоя нет), —
  такие листы распознаются OCR, как сканы.
- **Лист PDF — одна страница Word.** pdf2docx воспроизводит положение блоков точными отступами,
  и лист, заполненный до штампа, в Word оказывался «впритык»: толщина линий, пустые строки-заполнители
  и интервалы по умолчанию (10 pt после абзаца в шаблоне) выталкивали хвост на лишнюю страницу. Теперь
  высота каждого листа оценивается вместе с колонтитулами, и при нехватке места сокращаются пустые
  отступы, затем интервалы, затем нижняя строка последней таблицы (`app/docxfix.py`, `fit_pages`).
- **Сжатые буквы.** Word при выгрузке в PDF записывает «масштаб» символов; pdf2docx его терял, и коды
  в узких графах («ЕХ.08.3.07.01-0035.01») переносились на две строки. Масштаб считается по ширине
  букв в PDF и встроенным шрифтам MuPDF с метриками Arial/Times/Courier (`app/textfix.py`).
- **Таблицы в LibreOffice и Р7-Офис.** pdf2docx задавал ширину ячеек, но оставлял равномерную сетку
  столбцов — редакторы, которые читают сетку, «расползали» таблицу. Сетка пересчитывается по ячейкам,
  дубли `w:tcMar` убираются (Word мог счесть файл повреждённым), пустые ячейки получают кегль таблицы.
- **Абзацы и списки** опросных листов: пункт «− …» (минус из шрифта Symbol) начинает новый абзац, у
  двухстрочных абзацев сохраняется красная строка.
- **Основная надпись любой ширины** (штамп Word-шаблона во всю рамку A4, нарисованный по ячейкам)
  находится по вертикалям, доходящим до низа рамки, и словам граф («Изм.», «Лист», «Подп.»).

### Каталоги и прайсы из Word (таблицы на десятки строк)

Такие PDF (Word → PDF, в том числе через онлайн-сервисы) рисуют каждую линию каждой ячейки отдельной
тонкой заливкой — на листе 1–2 тысячи элементов. Раньше каталог на 25 листов конвертировался 85 с и
давал 38 страниц с рассыпанными таблицами; теперь — около 15 с и 25 страниц, лист в лист.

- **Скорость** (`app/speedups.py`). pdf2docx группировал элементы попарным перебором (O(n²) вызовов
  медленных методов `fitz.Rect`), копировал каждую страницу перед разбором и пересчитывал всю сетку
  таблицы python-docx при обращении к каждой ячейке. Те же группировки считаются сортировкой с
  проходом, снимок страницы — через pickle, сетка ячеек кэшируется. Результат побайтно совпадает с
  прежним (проверено на всех образцах и реальных документах; тесты сравнивают с перебором).
- **«Полосатые» таблицы** — строки разделены только серой заливкой через одну, без линий: по краям
  заливки ставятся невидимые границы строк, и каждая строка остаётся строкой таблицы.
- **Строка-подзаголовок группы без вертикалей** («Ду215 40 16» внутри таблицы крепежа): вертикали
  продолжаются через неё невидимыми — одна таблица вместо десятка кусков с абзацами между ними.
- **Текст соседних ячеек не склеивается.** Word кончает текст ячейки пробелом; склейка строк,
  разрезанных при выравнивании по ширине, теперь не переходит через линию таблицы.
- **Две таблицы рядом** больше не рвутся на «верх в две колонки + низ вложенной таблицей»: при
  делении листа на разделы таблица — один блок.
- **Белые поля картинок** обрезаются (чертёж с белым фоном заходил под соседнюю таблицу и
  выталкивал её под себя); повёрнутые на 90° картинки — без чёрной линии по краю.
- **Градиентные плашки и встроенные картинки** (заливка узором под шапкой каталога) — pdf2docx их
  не видел; теперь они рендерятся картинкой под текстом.
- **Логотип и название рядом** (шапка листа ОЛ, титул): блоки рядом в колонтитуле — таблицей без
  границ, а не друг под другом; тело листа начинается там же, где в PDF.
- **Обложка-фотоколлаж не распознаётся как текст**: если на «скане» почти нет слов, а фото занимает
  полстраницы, страница остаётся картинкой.
- **Строка заголовков таблицы под логотипом не уходит в колонтитул**, контур большой таблицы не
  принимается за рамку листа, а нижние строки таблицы — за штамп.
- **Подгонка «лист = страница»** считает лист PDF целиком (раздел «с новой страницы» и непрерывные
  разделы за ним; у раздела в две колонки — по высоте большей колонки).

### Выгрузка в Excel (`app/xlsxexport.py`)

Пример у тестировщиков — ContentReader PDF: «Сохранить как → Рабочая книга (XLSX)». Здесь Excel
строится из готового DOCX, поэтому в нём та же структура таблиц, что и в Word:

- лист книги на каждую страницу PDF («Стр. 7»); страницы без текста (обложка-картинка) пропускаются;
- таблицы — с объединёнными ячейками, границами, заливкой, жирным шрифтом и шириной колонок;
  вложенные таблицы-раскладки pdf2docx (две таблицы рядом) — рядом на листе;
- числа («50», «3,0», «105,25») — числами с тем же числом знаков; коды, диапазоны и размеры
  («0162», «400-8000», «1100х600») — текстом;
- абзацы — строками; табуляция раскладывает строку по колонкам (содержание, «Таблица 1» справа);
- спецификации ГОСТ, где позиции идут столбиком в одной высокой ячейке без линий между ними,
  делятся на записи: абзацы разных колонок, перекрывающиеся по высоте, — одна строка Excel;
- картинки, колонтитулы и штампы в Excel не переносятся. Сбой выгрузки не мешает получить DOCX.

### Что исправлено поверх pdf2docx (`app/textfix.py`)

pdf2docx — лучший свободный движок «PDF → DOCX с макетом», но у него есть систематические ошибки,
которые здесь устранены:

- **Выравнивание по ширине принималось за таблицы.** MuPDF режет такую строку на отдельные слова,
  и pdf2docx собирал из абзацев десятки «невидимых» таблиц. Теперь фрагменты одной строки,
  разделённые настоящим пробелом из PDF, склеиваются ещё до разбора; оставшиеся ложные таблицы
  ловятся проверкой и страница перепарсивается без них.
- **Слова склеивались на переносах строк** («трансформацияпроизводственных»).
- **Пропадал пробел после номера** («1.Анализ») и маркеры списков из шрифтов Symbol/Wingdings
  показывались «квадратиками».
- **Пункты списка сливались в один абзац** — в pdf2docx эта проверка отключена (`if 0 and …`).
- **Обрезался текст в ячейках** из-за «точной» высоты строк таблиц.
- **Колонки разъезжались вне MS Word.** pdf2docx раскладывает колонки по разделам «со следующей
  колонки», которые понимает только Word; LibreOffice, R7-Офис и другие разносили текст по лишним
  страницам. Теперь это один раздел с явным разрывом колонки.
- **Пробел между строками из разных блоков** ставился только для латиницы — русские слова слипались
  («2026 г.Срок»).
- **Обход бага PyMuPDF**: обращение к `needs_pass` после ввода пароля ломало расшифровку AES
  (проявляется в 2.x) — документ расшифровывается в память сразу после ввода пароля.

## API

Документация Swagger: `/api/docs`.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/config` | лимиты, доступность OCR, языки |
| `POST` | `/api/tasks` | загрузка PDF (`multipart/form-data`, поле `file`) → задача с числом страниц и превью |
| `GET` | `/api/tasks/{id}` | статус: `uploaded` / `queued` / `processing` (+`progress`, `stage`) / `done` / `error` |
| `GET` | `/api/tasks/{id}/thumb` | превью первой страницы (PNG) |
| `POST` | `/api/tasks/{id}/unlock` | `{"password": "…"}` — проверить пароль, получить превью и число страниц |
| `POST` | `/api/tasks/{id}/convert` | `{"ocr": "auto"\|"off", "ocr_lang": "rus+eng", "pages": "1-3", "password": "…"}` |
| `GET` | `/api/tasks/{id}/download` | готовый DOCX; `?format=xlsx` — таблицы и текст в Excel (если `has_xlsx`) |
| `GET` | `/api/zip?ids=a,b,c` | все готовые документы ZIP-архивом |
| `DELETE` | `/api/tasks/{id}` | отменить конвертацию и удалить файлы |
| `GET` | `/healthz` | проверка работоспособности |

Пример из командной строки:

```bash
ID=$(curl -s -F "file=@report.pdf" localhost:8000/api/tasks | jq -r .id)
curl -s -X POST -H 'Content-Type: application/json' -d '{"ocr":"auto"}' localhost:8000/api/tasks/$ID/convert
curl -s localhost:8000/api/tasks/$ID | jq '.status, .progress'
curl -OJ localhost:8000/api/tasks/$ID/download
curl -OJ "localhost:8000/api/tasks/$ID/download?format=xlsx"
```

## Ограничения

Конвертация PDF в Word — восстановление структуры по координатам, а не обратное преобразование:
в PDF нет абзацев, стилей и таблиц, только символы и линии. Поэтому:

- сложные макеты (журнальная вёрстка, текст поверх картинок, повёрнутый текст) переносятся с
  упрощениями; ширина колонок безрамочных таблиц может отличаться от оригинала;
- автонумерация и стили абзацев не восстанавливаются (кроме заголовков — см. выше), форматирование прямое;
- формулы и сложная векторная графика переносятся картинками;
- OCR: таблицы восстанавливаются только при наличии линий сетки; курсив не определяется;
  качество зависит от скана (оптимально 300 dpi); ~2–4 с на страницу;
- шрифты, которых нет на компьютере, Word заменит похожими (для чертёжных шрифтов вроде ISOCPEUR
  и GOST type A это может удлинить строки — установите их на компьютере);
- оформление листа ищется по геометрии и повторам; на листах с поворотом (`/Rotate`) оно остаётся
  в тексте страницы, как раньше.

## Лицензии зависимостей

PyMuPDF распространяется под AGPL-3.0 (или коммерческой лицензией Artifex), pdf2docx — MIT,
openpyxl — MIT, Tesseract — Apache-2.0. PyMuPDF ограничен версиями `<2`: ветка 2.x тянет `pymupdf-layout`
с некоммерческой лицензией. Подробнее — в [docs/DEPLOY-CORP.md](docs/DEPLOY-CORP.md#лицензии-компонентов).

```bash
pip install -r requirements-dev.txt
```

Набор образцов: отчёт из Word с таблицами, графиком и колонтитулами; двухколоночная статья с

## Работа в продакшене

- Поставьте перед сервисом nginx с HTTPS и увеличенным лимитом тела запроса:

  ```nginx
  location / {
      proxy_pass http://127.0.0.1:8000;
      client_max_body_size 110m;
      proxy_read_timeout 120s;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header X-Forwarded-Proto $scheme;
  }
  ```
- Встроенной авторизации нет: для внутреннего использования закройте доступ на уровне сети/SSO
  (например, oauth2-proxy), для публичного — добавьте ограничение частоты запросов.
- Один экземпляр uvicorn на хост; производительность масштабируется через `CONVERT_WORKERS`
  (≈ 1 ядро и 0,5–1,5 ГБ памяти на одновременную конвертацию).
